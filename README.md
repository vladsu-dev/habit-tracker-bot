# Трекер привычек в Telegram

Личный чат с ботом позволяет планировать ежедневные привычки, отмечать результат и получать напоминания. FastAPI проверяет владельца при каждом обращении к привычке.

## Запуск

1. Установите и запустите Docker с Compose. Откройте терминал в корне проекта.
2. Если файла `.env` ещё нет, скопируйте `.env.example` в `.env`. Для `POSTGRES_PASSWORD` и `BOT_SERVICE_KEY` задайте два разных случайных секрета. Для каждого можно отдельно выполнить `openssl rand -hex 32`.
3. Создайте бота через `/newbot` в официальном [BotFather](https://t.me/BotFather). Сохраните выданный токен в `TELEGRAM_BOT_TOKEN` в локальном `.env`. Секреты исключены из Git и контекста сборки.
4. Выполните `docker-compose up`. При первом запуске Compose собирает приложение, поднимает PostgreSQL, применяет миграции и запускает API, бот и процесс напоминаний. Команда `docker-compose up --build` пересобирает приложение после правок.
5. Откройте личный чат с ботом, отправьте `/start`, выберите «Регистрация» и введите отдельный пароль длиной от 8 до 128 символов. Для остановки используйте `docker-compose down`. Именованный том сохраняет данные между запусками.

## Работа в чате

- `/today` открывает привычки на сегодня. Отметка «Не выполнил» отличается от отсутствия ответа. Нажатие можно исправить до конца местного дня.
- `/add` создаёт привычку. Введите название и выберите цель по умолчанию в 21 выполнение либо задайте свою.
- `/all` открывает все привычки для редактирования и удаления, включая достигшие цели. Удаление с подтверждением стирает привычку и её отметки.
- `/settings` меняет часовой пояс и время напоминаний. Начальные значения — UTC и 20:00. Например, для Москвы укажите `Europe/Moscow`.
- `/logout` отзывает токен текущего сеанса. Для следующего входа используйте `/login`.

Одна успешная отметка за местную дату даёт одно выполнение. Пропуски сохраняют накопленный результат. В день достижения цели отметка ещё доступна для исправления. На следующий день список пересчитывается по сохранённым отметкам. Увеличение цели возвращает привычку в активный список, если выполнений снова недостаточно.

## Устройство проекта

| Компонент | Назначение |
| --- | --- |
| `app/bot.py`, `bot_presenter.py`, `bot_view.py` | Приём обновлений pyTelegramBotAPI, управление диалогом и представление меню |
| `app/main.py`, `auth.py`, `accounts.py` | FastAPI, регистрация, вход, отзыв токена и модель пользователя |
| `app/habits/` | Контроллер HTTP, схемы ввода, модели и правила дневного трекинга |
| `app/reminders.py` | Отдельный процесс опроса расписаний и журнал доставки |
| `app/database.py`, `migrations/` | SQLAlchemy, PostgreSQL и версия схемы Alembic |

Идентификатор берётся из личного Telegram-обновления. Бот предъявляет сервисный ключ при регистрации и входе, а в дальнейших запросах передаёт пользовательский Bearer-токен. Пароль хешируется через scrypt со случайной индивидуальной солью. База хранит хеш токена. Сеанс действует семь дней, повторный вход заменяет предыдущий токен. После пяти неверных попыток вход блокируется на 15 минут. После перезапуска процесса бота для работы с меню требуется войти снова.

Пароль передаётся обычным сообщением Telegram. Бот пытается удалить его сразу после получения, поэтому для сервиса нужен отдельный пароль. Выход закрывает будущие запросы. Сообщения с привычками, которые уже доставлены в Telegram, остаются в истории чата. Восстановление забытого пароля в этой версии отсутствует.

Процесс напоминаний сверяет местное время каждые 30 секунд. После назначенного времени он отправляет ещё не отмеченные привычки. Если срок серверного сеанса истёк или пользователь вышел, приходит общее напоминание без названий. Запись об успешной доставке исключает штатную повторную отправку за ту же дату. При остановке процесса между ответом Telegram и записью в БД возможен повтор. Напоминания за полностью пропущенные дни не рассылаются.

## Проверка разработки

В проекте используется Python 3.13. Установите зависимости и запустите проверки:

```sh
poetry install
poetry run pytest -q
poetry run ruff check .
```

По умолчанию тесты используют временные базы SQLite и подменяют Telegram. Для проверки на **отдельной тестовой базе PostgreSQL** задайте `DATABASE_URL` в формате `postgresql+psycopg://user:password@host/dbname`, выполните `poetry run alembic upgrade head`, затем `poetry run alembic check` и `poetry run pytest -q tests/test_service.py`. Интеграционный тест создаёт временную учётную запись, проверяет в том числе конкурентные отметки и удаляет тестовые данные.
